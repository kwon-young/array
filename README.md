# array

Multidimensional arrays for SWI-Prolog, written as boxes of equations and compiled to OpenCL.

A program is a sequence of `over/2` boxes.
Each box runs its equations at every point of its axes, like a loop nest, and an equation writes one element of an array.
From these boxes the compiler derives the kernels: which axes are parallel, what fuses, what lives in registers or local memory, and how the intermediates share one arena.
It prints them as OpenCL C and runs them on any OpenCL device.
A reference interpreter, `eval/3`, runs the same boxes in Prolog, exactly, to check the device against.

Shapes and subscripts are clpBNR constraints.
So an extent may stay unknown: one compiled program then serves every size, and a subscript out of bounds is an error before anything runs.

## Installation

You need:

- a recent SWI-Prolog (developed on 10.0), with its development headers;
- CMake 3.16 or later and a C compiler;
- the OpenCL headers and ICD loader (`opencl-headers` and `ocl-icd-devel` on Fedora), and at least one OpenCL runtime (pocl, or a GPU vendor's);
- the [clpBNR](https://github.com/ridgeworks/clpBNR) pack, which `pack_install` installs as a dependency.

### As a pack

```
swipl pack install https://github.com/kwon-young/array.git
```

The pack manager builds the foreign libraries with CMake into `lib/<arch>/`, runs the test suite, and installs.

### From a checkout

```
cmake -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

To use the checkout from anywhere, link it as a pack: `swipl pack install . --link` (or `pack_install('.', [link(true)])`).

## A first program

```prolog
:- use_module(library(array)).

% C = A B, for A of N x M and B of M x P.
matmul(A, B, C, N, M, P) :-
   shape(A, [N, M]), shape(B, [M, P]), shape(C, [N, P]),
   over([I:N, J:P], [C[I, J] := 0]),
   over([I:N, J:P, K:M], [C[I, J] := C[I, J] + A[I, K] * B[K, J]]).
```

```prolog
?- matmul(A, B, C, 2, 3, 2),
   Data = [A-[1, 2, 3, 4, 5, 6], B-[1, 0, 0, 1, 1, 1]],
   eval(C, Data, Ref),
   run(C, Data, Values, [device(pocl)]).
Ref = Values, Values = [4.0, 5.0, 10.0, 11.0].
```

Data gives the elements of each input, row-major, and the results come back the same way.
`opencl_device(Name, Device)` enumerates the devices; `run/4` takes `device(Name)`, pocl by default.
`kernels(C, Options, Kernels)` and `source(Kernels, Source)` show the kernels and their OpenCL C.

## Vocabulary

- **Name**: an array is a Prolog variable, never bound.
  Its definition hangs on it as an attribute: its shape, and the boxes that write it.
- **Axis**: `I:N` is an index `I` over an extent `N`, an integer or a clpBNR integer variable.
- **Box**: `over(Axes, Equations)` runs its equations at each point of its axes, in lexicographic order.
  An equation may itself be a box.
- **Equation**: `A[Ts] := V` writes the value `V` at the place `A[Ts]`.
  A read `A[Es]` is the current content of a place; a name alone is its rank-0 place.
- **Values**: numbers, indices and reads, combined by `+ - * / max min exp sqrt log`, the comparisons `< =< =:=`, `where(Cond, Then, Else)`, and on ints `// mod >> << /\ \/ xor`.
- **Kinds**: every name holds bools, ints or floats.
  A written name takes the greatest kind of the values written to it, and an input is float unless `kind/2` declares it.
- **Declarations**: `elements(Idx, Lo-Hi)` bounds the values of an int input, `permutation/1` declares its elements distinct, and `power_of_two/1` declares an extent a power of two.

## The library

| Module | |
|---|---|
| `library(array)` | The user-facing predicates: the vocabulary, `program/2`, `eval/3`, `kernels/3`, `source/2`, `run/4`, `device_options/2`, `opencl_device/2`. |
| `library(array/core)` | The vocabulary, its checks, and the clpBNR hulls of subscripts. |
| `library(array/compile)` | The pipeline: program, fuse, schedule, print, allocate, run. |
| `library(array/reference)` | `eval/3`, the boxes compiled to a Prolog clause; with the flag `eval_cache`, results cached under `~/.cache/array_eval`. |
| `library(array/minimalloc)` | The [MiniMalloc](https://dl.acm.org/doi/10.1145/3623278.3624752) static allocator, which lays out the intermediates in one arena. |
| `library(array/opencl)` | A thin binding of the OpenCL host API (foreign, `src/opencl.c`). |
| `library(array/buffer)` | Typed host buffers (foreign, `src/buffer.c`; its type conversions are generated by `src/gen_type.pl`). |

## Examples

`examples/` holds programs written with the library:

- `linalg.pl`: matmul, dot, and Cholesky factorizations, plain, blocked and batched;
- `nn.pl`: softmax, a transformer MLP, layer norm, a ViT encoder block, scatters and an embedding backward pass;
- `sort.pl`: bitonic and LSD radix sorts of float keys with their payloads;
- `ukf.pl`: one step of an unscented Kalman filter, batched over tracks and detections.

## Tests

```
swipl -g test_array -t halt test/test_array.pl
swipl -g "test_array(compile_basics)" -t halt test/test_array.pl
ctest --test-dir build --output-on-failure
```

Every test is a `.plt` file in `test/`, each a module of its own.
`test/test_array.pl` loads them all, putting the checkout's `prolog/` and `lib/<arch>/` before any installed copy.
Tests that run kernels run on every OpenCL device found.

## Benchmarks

`bench/` times the kernels against PyTorch:

- `bench.pl`: the harness (`bench_data/6` prints the best kernel time and the memory of the intermediates) and the runs of the examples, `go/1`, `go_chol/1`, `go_vit/1`, ...;
- `bench_sort.pl`, `bench_ukf.pl`, `bench_alloc.pl`, `bench_minimalloc.pl`, `sweep.pl`;
- `*.py`: the same programs in PyTorch;
- `probe/`: experiments on single kernels;
- `minimalloc/`: the challenging problems of the original MiniMalloc project.

For example, from `bench/`, with the pack installed or linked:

```
swipl -g "go(nvidia)" -t halt bench.pl
```

## Status

The library is a research prototype; its interface changes.
`archive/` holds earlier designs (a NumPy-like dict array with views, a kernel IR and C, OpenCL and Prolog runtimes), which no longer load.
